# Host and VM log collection

The Linux collector sends audit executions, system journal entries and Docker stdout/stderr to `https://api.hanasand.com/api/logs/ingest`. Original levels are retained; Mill assigns the separate detection severity. Every execve/execveat from every user and service is audited. Shell built-ins do not create execve events; a shell invocation retains its command arguments. Audit collection requires root and kernel audit support.

The collector is maintained here in TypeScript: `core.ts` owns redaction, durable queues and HTTP delivery; `sources.ts` reads host logs; `guests.ts` handles LXD exports; `collector.ts` runs independent Node worker threads. `configuration.ts` manages protected configuration and audit retention. There is no Python runtime dependency.

Build with `bun install --frozen-lockfile && bun run build` in this directory. The resulting `dist/collector.cjs` has no runtime npm dependencies. Node 18.15+ and systemd are required on Debian/Ubuntu; the installer checks the runtime and installs the distribution Node package when needed. Run `install.sh <host-id>` as root. It installs persistent audit rules, the collector and an enabled service, but does not start delivery. Configure its protected credential, then start it only after the ingestion API is ready:

```sh
/usr/local/sbin/hanasand-log-collector --configure inspur /path/to/protected/log-ingest.json
systemctl start hanasand-log-collector
```

The credential source is a root-restricted JSON object containing `LOG_INGEST_TOKEN`, generated outside source control. `--configure` preserves existing collection start time, writes mode 0600 and prints no credential. Use the dedicated ingestion credential, never a human session or a broad VM API token. A remote credential may be supplied on standard input with `-`. Do not put it in command arguments, logs or shell history.

State and the outgoing queue are stored on disk under `/var/lib/hanasand-log-collector`. Each bounded JSON batch is flushed to disk before its source cursor advances. The sender reuses an authenticated HTTPS connection to the existing ingestion API; HTTP 201 with `ok: true` and the exact accepted count acknowledges the database transaction. Only then is that batch file deleted. A lost response or restart replays the same stable event IDs, which the receiver deduplicates. No new SSH listener or WebSocket endpoint is needed.

Recent events and historical replay have independent senders and queue directories, so a slow historical request cannot block new logs. History yields while the live queue has pending batches, preserving receiver capacity for current traffic. Readable Docker JSON files are followed every 100 ms, with independent journal and audit live passes every second. Delivery starts as soon as a queue batch is durable. The target for new host logs is under 10 seconds from collection to committed ingestion while the host, network and receiver are healthy. Outages retain the backlog on disk and retry; they cannot satisfy a finite delivery deadline. Last acknowledgement time, queue age and delivery errors appear in `health.json` and collector health events. A live acknowledgement taking 10 seconds or more is reported as a failure.

Audit and journal output is read through bounded pipes, one event at a time, and immediately queued as JSON. Historical audit queries cover at most one minute per pass, including empty windows. Docker CLI fallback and guest exports use scratch files on the persistent state volume rather than `/tmp` (which may be RAM-backed). Outgoing buffers hold at most 100 events or approximately 256 KiB, with an individually bounded larger event allowed up to the ingestion limit. Queue size does not set process memory size. The collector only prepares the existing event envelope and redacts credentials; detection and indexing remain at the receiver. Source files are not deleted or rewritten by the collector.

Sources run independently. Journal rotation resumes by timestamp; audit rotation uses ausearch checkpoint recovery. Docker CLI fallback reads one minute at a time, and readable JSON files use inode/offset checkpoints. Canonical IDs include [Docker’s nine-digit timestamp padding](https://docs.docker.com/reference/cli/docker/container/logs/); single-line CLI replay IDs remain unchanged. Plain CLI text cannot always distinguish timestamp-shaped continuation lines or adjacent unterminated records; JSON record boundaries are authoritative. `HANASAND_LOG_CONFIG` and `HANASAND_LOG_STATE` support restricted user services without granting audit access.

When Docker removes a container and its source files disappear, collection preserves the acknowledged cursor files and archives the source after durably queueing one stable high-severity notice that final coverage is unknown. A same-name replacement automatically adopts readable JSON-file collection with its own identity and existing cutoff. CLI collection never scans timestamps before the verified container creation time. Retired unavailable sources remain counted in source health details; their files cannot be reconstructed.

Uncompressed rotated files are completed in order. Active partial JSON lines wait for completion; a closed rotated fragment is preserved as a redacted error event with byte length/hash/offset before advancing. Truncation or unavailable file identity generates an explicit notice before retained contents are replayed. Sources with existing gzip archives remain on the CLI. If compressed history appears after enrollment, the file history cursor stops with an explicit error; the independent live path continues, and no compressed history is silently skipped. Other drivers and sources without local file permissions continue using the CLI. No source files or retention settings are changed.

On LXD hosts, the collector discovers running guests every 30 seconds, installs the same audit rules and reads guest audit, journal and Docker events through LXD. Each guest keeps an export spool and separate cursors until the host acknowledges durable queueing for ingestion. The ingest credential never enters a guest. Guest events identify both the physical host and VM. Stopped guests are left stopped and enrolled the next time they run; installation/network failures remain visible in high-severity collector health events. This cannot collect events occurring before a new guest's first audit enrollment. Full VMs need a working LXD agent; unprivileged containers cannot independently enable kernel auditing and report that limitation.

The installer raises small rotating audit stores to 100 MB per file and 20 files when disk space permits, leaving at least another 2 GB free. Existing larger retention and non-rotating security policies are preserved; existing audit files are not deleted. Unavailable historical source files cannot be reconstructed by the collector.

Structured secret fields, common password/token flags, HTTP credentials, cookies and authorization values are redacted before delivery. Redaction is best effort: positional or unusually named secrets may remain in command arguments, so log access must remain restricted. Source output is not modified. The Linux collector does not cover macOS, unreachable hosts or machines lacking administrative access; report those gaps explicitly.

Run `bun run typecheck`, `bun run test`, `bun run test:node`, and `bun run test:memory`. The Node integration test executes the actual bundled service with worker threads and a legacy queued batch. The memory check streams 100,000 audit events (over 200 MB) with a 250 MB peak-memory limit.

For existing hosts, stage `dist/collector.cjs` as `collector.cjs` alongside `deploy.sh`, `install.sh`, `launcher.sh`, and `ovh-memory.conf`, then run `sh deploy.sh <full-commit>`. This uses root or the existing sudo installation/service-management permissions, retains configuration, queues and cursors, and backs up the previous executable under `/var/lib/hanasand-log-collector/rollback/<commit>`. A release passes only when the new service reports its revision, fresh live source checks, and an HTTP ingestion acknowledgement. Failed activation restores the previous executable. Existing Python-format queues, source cursors, and guest exports remain readable; event IDs stay stable across replay. Running guests receive the Node artifact through the existing LXD enrollment flow; stopped guests update when next running.

 Verify a real harmless `whoami` execution reaches Mill as `ProcessLogs` on each enrolled host and guest; dangerous patterns belong only in synthetic fixtures.
